# 引き継ぎメモを最新にする

実務担当（せどり）の Claude が、次のセッションに情報を漏れなく渡すための手順です。メモは Google ドライブ「せどり記録」フォルダの文書「せどり 引き継ぎメモ（実務担当向け）」（ID `1smO6gaDUoIJ4Iy-xuTleU8winiKvIOvV9RoKA_4ZJb0`）。

## 手順

1. **いまのメモを読む**: Google ドライブのコネクタで上の文書を読む（`read_file_content` など）。見出しは次の7つ。
   1. 利用者について
   2. 決めたことと理由（新しいものを上に）
   3. 利用者との約束（まだ果たしていないもの）
   4. まだ終わっていないこと・利用者に確認中のこと
   5. 定期作業の状態
   6. 場所の一覧
   7. 作業のコツ・気をつけること
2. **材料を集める**:
   - この会話で利用者と決めたこと・約束したこと・終わったこと（会話をさかのぼって拾う）。
   - 定期作業の今の状態: `list_triggers` で実務担当の定期作業（名前「せどり実務担当の毎朝の作業」）と1回だけの予約を確かめ、ID・時刻・届くセッション・有効かどうかを書く。プロンプトの全文は書かない（要点だけ）。
   - このセッションの ID（`get_session`）。
   - リポジトリの最近のコミット（`git log --oneline -10`）と、正式な場所にマージ済みか。
   - 「実務担当からの共有（せどり）」の最新の日付の項目（ほかの担当に伝えたこと）。
3. **書き直す**:
   - 終わったことは「3. 約束」「4. まだ終わっていないこと」から消し、必要なら「2. 決めたこと」に結果を1行で残す。
   - 新しく決めたことは「2.」のいちばん上に「日付 何を決めたか（だれの決定・依頼）。理由: 〜」の形で足す。理由が分からないときは「理由: 未確認」と書き、利用者に確かめる。
   - 前の担当から伝わっていなかったことに気づいたら、思い出せる範囲で足す（どこから分かったかを添える）。
   - 「最終更新」の日付とセッション ID を直す。
   - 平易な日本語で、1項目1〜3行。細かい仕組みの説明は sedori/README.md に書き、メモには場所だけ書く。
4. **書いてはいけないもの**: API キー・アプリIDの値、パスワード、口座・カード番号、スプレッドシートの記録の中身（仕入れ値や売上の一覧）。キーや ID は「環境変数 KEEPA_API_KEY にある」のように名前だけ書く。
5. **書き込む**: 文書の本文を、見出しの並びを保ったまま置き換える（Google ドキュメントのコネクタの `update_doc` で古い本文を消して新しい本文を入れる、など）。書いたあと読み直して、7つの見出しがそろっていることを確かめる。
6. **利用者に報告する**: 何を足した・消したかを3〜5行で伝え、メモのリンクを添える。理由が分からず「未確認」にした項目があれば、そこだけ質問する。

## ふだんの決まり（このスキルを使わないときも）

- 決めたことは、決めたその場でメモの「2.」に1行足す（会話の終わりまで待たない）。約束をしたら「3.」に足し、果たしたら消す。
- 定期作業を作り直した・止めた・手順を変えたら「5.」を直す。
